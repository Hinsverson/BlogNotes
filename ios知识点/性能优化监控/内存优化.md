# 场景内存优化场景
1. ARC内存泄露问题：
	1. 循环引用，一般场景就是系统一些api强持有target、timer、或者block捕获时，解决办法就是weak打破循环引用。
	2. OC或者C，以及Swift向堆动态内存分配一定要手动释放。
	3. OC对象和CF对象交互时，通过bridge技术管理内存，注意管理权限的移交和引用计数的变化，当不受ARC管理时要手动调用对应方法释放CF对象。
	4. Swift层面和CF对象交互时，通过UNManage管理，因为swift只支持ARC，系统对系统层产生的CF对象会在编译时通过关键字标示自动处理释放问题，相比OC不需要手动释放CF对象。但是要注意转换时根据实际场景下对对象生命周期的需要问题，选择传/取时增不增引用计数，以及成对的计数。
2. 图片内存占用处理：（ASDK这种是牺牲内存来换取流畅性）
	1. 使用ImageIO或者CG的重绘大图到实际展示的大小，而避免直接解码大图片时的大量内存占用。
	2. 大图片的展示，在前后台切换时，可以unload再reload的。
	3. 经常使用的图片才使用imageNamed方法。
	4. 超大长的图片考虑使用CATiledLayer来进行分片加载。
3. autoReleasePool快速释放autoRelease对象：
	1. swift中这东西没用，swift的临时对象管理在出了作用域后就释放了，只用在和OC交互时。
4. layer光栅化缓存占用：
	1. 对于不复杂，又不频繁使用的图层不要开启光栅化做渲染缓存。而且它还会引入离屏渲染的问题。
5. 其他的一些太细的东西：
	1. 声明属性和变量时，考虑字节对齐。
	2. 总之就是及时清理缓存占用。
	3. 渲染时，CVPixelBuffer或者其他纹理对象要注意使用对应的cache来管理（释放的时机完全由系统决），实际是一种缓存思想，避免大量重复对象的alloc开销占用。
