# 总结-算法设计

#  LRU算法
[146. LRU 缓存机制 · Issue #157 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/157)
根据描述：首先要接收一个 capacity 参数作为缓存的最大容量，然后实现两个 API：
	1. 一个是 put(key, val) 方法存入键值对。
	2. 另一个是 get(key) 方法获取 key 对应的 val，如果 key 不存在则返回 -1。
	3. 要求，get 和 put 方法必须都是 O(1) 的时间复杂度。

分析这个Cache应具备3个条件：
	1. 元素必须有时序，以区分最近使用的和久未使用的数据。
	2. O(1)的查找考虑哈希表，但是无序。
	3. O(1)的删除，考虑链表。
因为链表删除快，但是无法通过index直接定位。哈希表查找快，但是无序。所以最终，这个结构应该是一个综合结构，用哈希表O(1)直接定位链表中的某个节点，再配合链表实现快速的查找和删除操作。

所以最终基本思路：**双向链表+哈希表来实现**，考虑如下几个问题？
	1. 为什么必须要用双向链表？
	因为删除操作的时间复杂度需要O(1)，而链表的删除需要拿到pre前驱节点，单链表不支持。
	2. 为什么要在链表中同时存储 key 和 val，而不是只存储 val？
	满容后既要O(1)删除最前面最旧未被使用的节点，还要把map中映射到该节点的 key 同时删除，所以node必须包含key信息。
	3. get逻辑如下：
		1. 如果节点存在，从链表删除再挂到最后，然后返回即可。
		2. 不存在返回nil。
	4. put逻辑：如下
		1. 节点存在的情况下，先删除旧节点再插入新的节点到链表尾部。
		2. 不存在则检查缓存容量是否已经满了，满了就删头节点，再插入新的节点到链表尾部。

具体对于双向链表的设计需要如下操作：
	1. addLast：添加是添加到双向链表后面，对tail做头插，注意插入的顺序，最好画图
	2. remove：移除节点操作
	3. removeFirst：移除第一头节点

# LFU算法：了解即可
同LRU一样的API操作，但是要求当缓存达到容量capacity时，则应该在插入新的键值对之前，删除使用频次（后文用freq表示）最低的键值对，如果freq最低的键值对有多个，则删除其中最旧的那个，都yeO(1)完成：

* 调用get(key)方法时，要返回该key对应的val。
* 只要用get或者put方法访问一次某个key，该key的freq就要加一。
* 如果在容量满了的时候进行插入，则需要将freq最小的key删除，如果最小的freq对应多个key，则删除其中最旧的那一个。

## 思路
使用一个HashMap存储key到val的映射，就可以快速计算get(key)。
使用一个HashMap存储key到freq的映射，就可以快速招待key对应的freq。
肯定还需要freq到key的映射，用来找到freq最小的key，同时可能有多个key拥有相同的freq，所以一个freq对应一个key的列表，而且freq对应的key的列表是存在时序的，便于快速查找并删除最旧的key。
