# 总结-算法思想

# 递归
递归的核心思想就是把规模大的问题转化为规模小的同类型子问题来解决，小到一定程度可以直接得出它的解。

所以分治思想同递归一样，一般分治的具体写法就是通过下面的递归模型二，先往下分然后在递归归来过程中治理（处理）。

* **递归的空间复杂度计算：**递归深度*辅助空间
* **递归深度：**不是函数调用次数，而是最大的栈空间分配次数。比如比如[剑指 Offer 10- I. 斐波那契数列 · Issue #77 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/77)中，在用公式法直接求解时，因为fib（n-1）执行完后才会开辟栈空间执行fib（n-2），所以空间复杂度是O(n)，当然时间复杂度是O(n^2)。
* **递归转非递归：**所有的递归都可以通过自己维护一个栈存参数和结果信息，从而转成非递归的形式。
* **尾递归：**尾递归一般发生在递归模型一前处理时，尾递归如果编译器支持栈帧修改的话效率上讲要高一点，应该优先选用。尾递归比线性递归一般多一个参数，这个参数是上一次调用函数得到的结果，所以关键点在于，尾递归每次调用都在收集结果，然后把结果向下传递从而避免了线性递归不收集结果只能依次展开开辟栈帧消耗内存的坏处。

### 模型一： 前处理，先处理问题然后再往下传递
``` swift
guard !递归终止条件 else { return }
//处理问题
递归函数（小规模）//一般要把处理结果传入下一层
```
比如树的DFS遍历中的前序遍历。
一般还要把处理结果传入下一层。

### 模型二： 后处理，在归来的过程中处理问题
``` swift
guard !递归终止条件 else { return }
递归函数（小规模）//一般要根据递归结果来处理本次的问题
//处理问题
```
比如树的DFS遍历中的后序遍历。
一般要根据递归结果来处理本次的问题，应该把结果抽象的看成一个已经处理完的整体。

### 递归的三要素
1. 首先不要想具体的代码怎么写，而是需要明确定义递归函数的功能，搞清楚这个函数的作用。
2. 明确原问题与子问题的关系，即寻找f(n)与f(n-1)的关系。
3. 明确边界条件，相当于思考问题规模小到什么程度可以直接得出解，然后退出递归。

# 二分查找
是一种特殊的分治思想，在有序数组中查找某一元素的搜索算法。

### 求解模型
[二分查找模版图片](https://assets.leetcode-cn.com/aliyun-lc-upload/uploads/2020/07/29/template_diagram.png)
建议优先选用下面的模版，左右闭区间。
```swift
//迭代的写法
func binarySearch(nums: [Int], target: Int) -> Int {
    var l = 0, r = nums.count - 1;
    //搜索区间为[l, r]
    while(l <= r) {
        let mid = l + (r - l) >> 1;
        if (nums[mid] == target) {
            //查找成功
            return mid;
        } else if (nums[mid] < target) {
            l = mid + 1 //搜索区间变为[mid+1, right]
        } else if (nums[mid] > target) {
            r = mid - 1 //// 搜索区间变为[left, mid-1]
        }
    }
    return -1 //没有找到的处理（注意越界的问题）
}
//递归的写法
func binarySearch(nums: [Int], target: Int, left: Int, right: Int) {
    if (l <= r) {
        let mid = l + (r - l) >> 1;
        if (nums[mid] == target) {
            //查找成功
            return mid;
        } else if (nums[mid] < target) {
            //新的区间，右半区间
            return binarySearch(nums,target,mid+1, r);
        } else if (nums[mid] > target) {
            //新的区间,左半区间
            return binarySearch(nums,target,l,mid-1);
		  }
    }
    return -1 //没有找到的处理（注意越界的问题
}
```
1. `left + (right - left) >> 1` 是为了防止了 left 和 right 太大直接相加导致溢出。
2. 因为right取的nums.count - 1，即最后一个元素的索引，搜索区间是闭区间，所以while要<=。
3. 同样因为是闭区间内搜索，left和right的区间更新时因为mid已经搜索过不符合条件了，所以更新是mid+1或者mid-1。
4. 退出循环的条件，l超过了r，也就是l = r+1。
5. 使用时要注意mid的更新变化处理，也是最容易出错的地方。

### 二分搜索场景
1. 基本搜索锁定：
	1. 找到时的处理：具体情况返回结果
	2. 没有找到的处理：具体情况返回结果。
	3. 没有找到的处理时要注意此时left = right+1可能是越界的。
2. 搜索并锁定左边界：找给定数在可能重复数组中出现的第一个位置。
	1. 找到时的处理：right = mid - 1 （别返回，收缩右边界，锁定左边界）
	2. 没有找到时的处理：检查 left 越界的情况（此时l = r+1）。
``` swift
//退出循环时：left = right+1，注意越界检查，此时l才是第1次元素出现的位置
guard l <= nums.count-1 && nums[l] == target else { return -1 }
return l  
```
3. 搜索并锁定右边界：找给定数在可能重复数组中出现的最后一个位置。
	1. 没有找到的处理：找到时的处理：left = mid + 1 （别返回，收缩左边界，锁定右边界）
	2. 没有找到的处理：检查 right 越界的情况（此时l = r+1）。
``` swift
//退出循环时：left = right+1，注意越界检查，此时r才是最后1次元素出现的位置
guard r >= 0 && nums[r] == target else { return -1 }
return r
```
4. 旋转数组二分搜索查找，先根据每趟的mid数与l数的大小关系一定能判断 mid 是在旋转的左段还是右段，再通过target和mid、l、r数的大小关系判断落在左边还是右边更新mid的位置。对于已经去重的数组mid==l数时可以看成mid大于l进行处理，存在重复的话只能更新`l += 1`。
5. 旋转数组找mid要通过mid数和r数去比较来收缩范围。

# 双指针
双指针的本质是通过2个指针，记录必要的信息，核心的处理就是如何通过移动它来解决具体问题，举一反三更高级的三指针也是同样的。

### 快慢双指针
1. 判定链表中是否含有环，以及已知链表中含有环，返回这个环的起始位置。
2. 寻找链表的特定位置元素，比如中点，倒数第n个元素。

### 前后双指针
1. 通过前后不断缩小范围覆盖所有情况找最值，类似滑动窗口。
2. 二分也是通过双指针前后逼近来完成。

# 滑动窗口
滑动窗口的思想是双指针思想的一种具体场景，一般用在一趟遍历过程中通过移动窗口2边的指针维护窗口范围，来覆盖所有的匹配情况，从而解决一些有多个解找出所有的解或者最优解的问题，它的基本思路是：
	1. 使用左右指针技巧，维护left和right之间形成一个窗口（依据具体问题确定初始位置，一般初始都在左边）。
	2. 增大窗口范围寻找一个「可行解」。
	3. 缩小窗口范围优化这个「可行解」，
	4. 重复2和3，最终找到最优解。

### 基本模型
滑动窗口基本处理模版如下，具体问题时应该具体分析，重点思考：
	1. 当移动right扩大窗口，应该更新哪些数据？
	2. 什么条件下，窗口应该暂停扩大，开始移动left缩小窗口？
	3. 当移动left缩小窗口，应该更新哪些数据？
	4. 我们要的结果应该在扩大窗口时还是缩小窗口时进行更新？
``` swift
var left = 0, right = 0
while /*直到窗口到达边界的条件*/ {
    window.add(s[right]) //添加保存必要信息
    right++ //增大窗口

    while /*window需要缩小的条件*/ {
        window.remove(s[left]) //移除保存的信息
        left++ //缩小窗口
    }
}
```

### 常见模型
一般滑动窗口使用过程中会配合哈希表来存储一些信息，尤其是匹配问题时，这些信息的存储和修改也就是基本模型里的数据更新操作，数据的更新操作通常是左右对称的，窗口左右收缩往往也需要依靠存储的信息做判断决议。

# 分治 
分治思想就是通过把大问题分成规模小的子问题，然后再合并子问题，推导出原大问题。类比树的后序遍历也是分治的一种体现，递归归来后的处理模型就是分治的典型实现，分治法具体处理步骤：
	* 递归返回条件
	* 往下划分子问题并递归求出解
	* 合并结果

**分治的运用前提：**分治不会缩减数据规模，但有时会提升算法性能。假如分治前O(n) = n^2，进行分治后，划归为2个子问题，每个子问题处理的时间复杂度为O(n/2) = (n/2)^2 = (n^2)/4，所以分治后总时间复杂度为O(n) = (n^2)/2，如果合并的时间小于(n^2)/2的话，对比分治前就是一种性能提升。

### 基本模型
``` swift
func traversal(_ root: TreeNode?) -> ResultType  {
    // nil or leaf
    if root == nil {
        // do something and return
    }
    // Divide
    let left = traversal(root.Left)
    let right = traversal(root.Right)
    // Conquer
    let result = Merge from left and right
    return result
}
```

## 回溯
[回溯算法解题套路框架 - labuladong的算法小抄](https://labuladong.gitbook.io/algo/suan-fa-si-wei-xi-lie/hui-su-suan-fa-xiang-jie-xiu-ding-ban)[力扣](https://leetcode-cn.com/problems/permutations/solution/hui-su-suan-fa-python-dai-ma-java-dai-ma-by-liweiw/)
解决一个回溯问题，实际上就是一个决策树的遍历过程，你只需要思考 3 个问题，**同时重点是如何维护选择列表和路径**。
	1. 路径：也就是已经做出的选择。
	2. 选择列表：也就是你当前可以做的选择。
	3. 结束条件：也就是到达决策树底层，无法再做选择的条件。

树的前序遍历的代码在进入child节点之前的那个时间点执行，树的后序遍历代码在离开child节点之后的那个时间点执行。

### 基本模型
``` swift
var res = []
func backtrack(路径，选择列表){
	if 满足结束条件 {
		res.append(路径)
      return
	}
	for 选择 in 选择列表 {
      //做选择前可能需要used去重复，去重处理就是从选择列表移除、添加
		做选择：将该选择从选择列表移除、路径.add(选择)
		backtrack(路径, 选择列表)
		撤销选择：路径.remove(选择)、将该选择再加入选择列表
	} 
}
```
![](%E6%80%BB%E7%BB%93-%E7%AE%97%E6%B3%95%E6%80%9D%E6%83%B3/B8B81FDE-5DE9-4445-8CC3-EC26C36DA265.png)
核心就是 for 循环里面的递归，在递归调用之前「做选择」，在递归调用之后「撤销选择」。
如果每次的选择列表是动态生成的，比较二叉树这种每次到达一个节点时，下一次可供选择的选择节点列表为非空节点列表，所以这时候不需要去重，如果是像排列组合这种，或者是图的DFS这种，一般需要用used表去重复。

### 剪枝优化

回溯算法的一个特点是不像动态规划存在重叠子问题可以优化，回溯算法就是纯暴力穷举，复杂度一般都很高O(N!)，所以能用空间换时间就尽量使用空间。

由于回溯算法的时间复杂度很高，因此在遍历的时候，如果能够提前知道这一条分支不能搜索到满意的结果，就可以提前结束，这一步操作称为剪枝。

回溯算法会应用「剪枝」技巧达到以加快搜索速度。有些时候，需要做一些预处理工作（例如排序）才能达到剪枝的目的。预处理工作虽然也消耗时间，但能够剪枝节约的时间更多。

> 提示：剪枝是一种技巧，通常需要根据不同问题场景采用不同的剪枝策略，需要在做题的过程中不断总结。

# 贪心
贪心算法可以认为是动态规划算法的一个特例，相比动态规划，使用贪心算法需要满足更多的条件（贪心选择性质），但是效率比动态规划要高。

贪心选择性质可以理解为，每一步都做出一个局部最优的选择，最终的结果就是全局最优。注意哦，这是一种特殊性质，其实只有一部分问题拥有这个性质。错误的应用贪心会得到错误的解。

有些题目需要把原数据进行处理，比如排序后才具备贪心选择性质，才能使用贪心。

# 动态规划
动态规划对比贪心能把所有情况都考虑到。一般考虑先暴力递归的思路求解，发现过程中出现很多因为自顶向下导致的重复计算后，再进行自底向上的递归，达到动态规划最优的目的。

动态规划技巧性比较高，难点是发现dp模型的能力和状态转移情况的梳理，从而能推出正确的状态转移方程。

### DP解题关键梳理：首先思考问题模型
1. 定义状态方程dp：一般是原问题或者相关子问题的解（难点，建模能力）
2. 设置初始化状态：dp(0)的值。
3. 确定转移方程：确定dp(i)和dp(i-1)的关系。
4. 考虑是否可以压缩dp表：看后面dp[i]的推算需不需要保留全部dp值。

整个DP执行过程层面可以理解为是在填写一个DP表，状态转移时需要借助前面一个或多个表项的结果，状态转移在最值问题的场景里一般是找DP表里的最值来确定下一个状态dp[i]的值。

有些时候dp表的定义就是原问题的答案，但是有些场景下问题的答案需要借助dp表的结果来求解，这种dp问题一般不容易定义状态方程，需要多总结和练习建立模型的能力，比如接雨水问题。

> dp表就是dp[i]的结果表，如果后续问题不需要使用全部dp[i]表的结果，那么还可以从空间上优化，比如[剑指 Offer 10- I. 斐波那契数列 · Issue #77 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/77)中，后续的项推导，只依赖于前2项，所以不用开辟数组dp表，而是直接用2个变量维护记录就好，这种思想一般称为状态压缩。  

### 可以使用DP求解的问题特点
1. 最优子结构：可以通过求子问题的最优解，不断推出原大问题的最优解。
2. 无后效性：在推导大问题时，只关心现阶段的状态值，和怎么来的没有依赖（未来和过去无关）。

> 理解上面2个特点，可以从现实场景理解，比如考试，“怎样才能考最高”这个问题的子问题是“每门科目考到最高”，“每门科目考到最高”这些子问题是互相独立，也就是具备最优子结构的特点，同时他们互不干扰，也就是具备无后效性。  
>   
> 无后效性可以和回溯的思想对比理解，回溯的特点是每选择一个路径之后需要从选择列表中移除这个选择子提供给下次决策使用，所以下次的决策依赖于上次的选择。[什么是无后效性？_涛声依旧的博客-CSDN博客](https://blog.csdn.net/qq_30137611/article/details/77655707)  

### 动态规划和分治的对比理解
动态规划（Dynamic Programming）与分治方法相似，都是通过组合子问题的解来求解原问题，区别在于：
* 分治方法将问题划分为互不相交的子问题，递归的求解子问题，再讲他们组合起来，求出原问题的解。
* 动态规划适用于子问题重叠的情况，即不同的子问题具有公共的子子问题。在这种情况下，分治算法会做许多不必要的工作，它会反复的求解这种公共子子问题。而动态规划算法中对每个子子问题都只求解一次，将其解保存在一个表格中，从而不用每次求解一个子子问题的时候都要重新计算，避免这种不必要的计算工作。

		2. 初始状态：dp[0] = 0表示没法凑。
		3. 状态转移： dp[amount] = min(1 + dp[amount - coin[i]]) for i in [0, len - 1] if coin[i] <= amount。
