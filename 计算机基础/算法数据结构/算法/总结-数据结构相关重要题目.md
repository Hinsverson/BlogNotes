### DFS访问：前序处理再传入结果 和 后序分治返回结果合并
``` swift
func preorderTraversal_dfs(root: TreeNode?) -> [Int] {
    var result = [Int]()
    dfs(root, &result)
    return result
}

// V1：深度遍历，结果指针作为参数传入到函数内部
func dfs(_ root: TreeNode?,_ result: inout [Int]) {
    guard let node = root else { return  }
    result.append(node.val)
    dfs(node.left, &result)
    dfs(node.right, &result)
}
// V2：通过分治法遍历
func preorderTraversal_dfs_a(root: TreeNode?) -> [Int] {
    let result = divideAndConquer(root)
    return result
}
func divideAndConquer(_ root: TreeNode?) -> [Int] {
    guard let node = root else { return [] }
    var result = [Int]()

    // 分治(Divide)
    let left = divideAndConquer(node.left)
    let right = divideAndConquer(node.right)
    // 合并结果(Conquer)
    result.append(node.val)
    result.append(contentsOf: left)
    result.append(contentsOf: right)
    return result
}
```
DFS 深度搜索（从上到下） 和分治法区别：前者一般将最终结果通过指针参数传入（前序处理），后者一般递归返回结果最后向上合并（后序处理）。

### 重要理解

::树的处理中经常要用递归，递归求解最重要的就是设计递归函数的输入参数依赖和输出，并牢牢记住这个函数的功能是啥？::

其此是递归的思想，首先要理解递归时的2种情况：
	1. 在递归前处理问题，并不断向下处理：在树遍历里一般和前序遍历结合。
	2. 在递归后处理问题，递归回来时处理：在树遍历里一般和后序遍历结合。

递归前处理的问题一般就是尾递归，尾递归如果编译器支持栈帧修改的话效率上讲要高一点，应该优先选用。

尾递归比线性递归一般多一个参数，这个参数是上一次调用函数得到的结果。所以，关键点在于，尾递归每次调用都在收集结果，避免了线性递归不收集结果只能依次展开开辟栈帧消耗内存的坏处。

典型递归：树的前、中、后序遍历是DFS深度优先思想，层序遍历是BFS广度优先思想，这2种思想要透彻理解，其中树的DFS前序遍历也是回溯思想的一种体现，树的DFS后序遍历也是分治思想的一种体现。

解决二叉树问题，首先想到框架就是遍历，DFS遍历里一般使用递归便于理解，如果求解问题时需要依赖左右子问题的解，那么就是需要用到DFS后序的递归，这种理解上有2种方式：
	1. 从顶到底看，先抽象得到子问题的解，根据左右子树上问题的解得到当前解。
	2. 从底到顶看，先分治，再从最左叶子节点开始向上求解每一个小树的解，最后推出根节点的解。

> 正常情况从上往下理解才是递归的精髓，和边相关的问题如果最终解可能不包含根节点，那么建议从下往上理解。  

二叉树找全局最值问题，就是在遍历过程中，拿到节点信息，搜集并不断比较和维护最值解。 [124. 二叉树中的最大路径和 · Issue #40 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/40)
二叉搜索树一般离不开前驱节点也是这个套路。[98. 验证二叉搜索树 · Issue #39 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/39)

### 重要理解
* 当需要修改链表上节点指针的指向时，要注意先保存后继节点信息的问题。
* 当涉及对头节点的操作，我们不妨考虑创建dummy哑节点。
* 链表节点的删除需要找到前驱（pre）节点，如果能获得被删除节点指针的话，那么可以把当前节点的值覆盖为后一个节点的值并删除后一个节点从而达到O(1)级别的删除（前提是节点不是尾节点）。[剑指 Offer 18. 删除链表的节点 · Issue #87 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/87)
* 当涉及对头节点的操作，同时需要按照统一规则处理链表的操作时，一般考虑新建dummy链表，同时用一个tail指针指示新链条的尾节点，在挂链完成后更新。同时一般也需要一个curr节点存储待处理的节点链。比如 [83. 删除排序链表中的重复元素 · Issue #147 · Hinsverson/AlgorithmTop · GitHub](https://github.com/Hinsverson/AlgorithmTop/issues/147)（注意保不保留重复节点的不同处理情况）

### 单调栈问题
[LeetCode Monotone Stack Summary 单调栈小结 - Grandyang - 博客园](https://www.cnblogs.com/grandyang/p/8887985.html)
就是使用stask存储结果，在push元素前对单调stack内部元素进行可能的pop处理，使得push新元素后，栈内依然具备单调递增或者递减的特性，从而达到O(1)的直接从栈顶取结果的效率。这类结构主要适用解决Next Great Number问题，也就是一维数组中，元素左侧（右侧）第一个大于（小于）它的元素类的问题。

不同的问题注意next数的处理时机，push前栈顶是即将push数的next数，发生pop时pop后新栈顶元素是pop出去元素向处理开始方向看的的next数，当前元素是向处理结束方向看的next数。

[单调栈参考图片](https://pic.leetcode-cn.com/7e876ae756613053b3432cebc9274e9dbdaafd2e6b8492d37fc34ee98f7655ea-图片.png)
单调栈分为单调递增栈和单调递减栈
	1. 单调递增栈即栈内元素保持单调递增的栈
	2. 单调递减栈即栈内元素保持单调递减的栈
操作规则（下面都以单调递增栈为例）
	1. 如果新的元素比栈顶元素大，就入栈
	2. 如果新的元素较小，那就一直把栈内元素弹出来，直到栈顶比新元素小
加入这样一个规则之后，会有什么效果？
	1. 栈内的元素是递增的
	2. 当新元素经过单调处理被加入栈前，栈顶元素就是新原素向前找第一个比其小的元素
	3. 当栈顶元素pop出栈后，新栈顶元素是pop出栈元素向前找第一个比其小的元素。要理解是因为之前加入这个被pop出去的元素时比它大的已经被踢走了（反过来单调递减栈就是向前找第一个比其大的元素）

解题总结
递增栈是维护递增的顺序，当遇到小于栈顶元素的数就开始处理，而递减栈正好相反，维护递减的顺序，当遇到大于栈顶元素的数开始处理。
	* ￼ 当前项向左找第一个比自己小的位置：从左向右维护一个单调递增栈 
	* ￼ 当前项向右找第一个比自己小的位置：从右向左维护一个单调递增栈
	* ￼ 当前项向左找第一个比自己大的位置：从左向右维护一个单调递减栈
	* ￼ 当前项向右找第一个比自己大的位置：从右向左维护一个单调递减栈 

单调栈模版
``` swift
let s = stack()
for 当前元素 in 所有元素 {
	  while !s.isEmpty(), 当前元素和s.top比较，加入后会破坏单调性时 {
        s.pop()
    }
    s.push(当前元素)
}
```
[图片地址](https://labuladong.gitee.io/algo/pictures/单调栈/1.jpeg)
记住这张图并理解下面这段关键代码：给你一个数组a [2,1,2,4,3]，你返回数组b [4,2,4,-1,-1]，b代表a中每个元素a[i]的右边第一个大于它的元素下标，没有就为-1（把数组的元素想象成并列站立的人，元素大小想象成人的身高）
``` c++
vector<int> nextGreaterElement(vector<int>& nums) {
    vector<int> ans(nums.size()); // 存放答案的数组
    stack<int> s;
    //当前项向右找第一个比自己大的位置
    for (int i = nums.size() - 1; i >= 0; i--) { // 倒着把元素往栈里放，出栈时就会正着出来更新结果，因为我要向后比较找最大。
        // 维护单调递减性，当前元素比栈顶大就pop直到小，因为要找大于，所以等于的情况也要pop
	      while (!s.empty() && s.top() <= nums[i]) { 
            s.pop(); //如果可以用当前元素替换栈顶元素（不符合）
        }
        // 新元素入栈前，栈顶元素就是往后看最大的数。
        ans[i] = s.empty() ? -1 : s.top();
        s.push(nums[i]); // 进栈
    }
    return ans;
}
```

给了边界的高度（黑色部分），让求能装的水量（蓝色部分）。 为啥能用单调栈来做呢？我们先来考虑一下，什么情况下可以装下水呢，是不是必须两边高，中间低呢？我们对低洼的地方感兴趣，就可以使用一个单调递减栈，将递减的边界存进去，一旦发现当前的数字大于栈顶元素了，那么就有可能会有能装水的地方产生。此时我们当前的数字是右边界，我们从栈中至少需要有两个数字，才能形成一个坑槽，先取出的那个最小的数字，就是坑槽的最低点，再次取出的数字就是左边界，我们比较左右边界，取其中较小的值为装水的边界，然后此高度减去水槽最低点的高度，乘以左右边界间的距离就是装水量了。由于需要知道左右边界的位置，所以我们虽然维护的是递减栈，但是栈中数字并不是存递减的高度，而是递减的高度的坐标。这应该属于单调栈的高级应用了，可能并不是那么直接就能想出正确的解法。

### 图DFS遍历访问
[关于图的DFS写的好的总结](https://leetcode-cn.com/problems/number-of-islands/solution/dao-yu-lei-wen-ti-de-tong-yong-jie-fa-dfs-bian-li-/)
``` swift
//对（r, c）这个点做DFS
func dfs(gird: inout[[Character]], _ r: Int, _ c:Int) {
    //判断坐标 (r, c) 是否在网格中
    guard r >= 0 && r < gird.count && c >= 0 && c < gird[0].count else { return }
    //如果是海洋，直接返回
    guard gird[r][c] != "0" else { return }
    //如果是已经标记过的节点，直接返回
    guard gird[r][c] != "2" else { return }
    
    gird[r][c] = "2" // 将格子标记为「已遍历过」
    
    // 访问上、下、左、右四个相邻结点
    dfs(gird: &gird, r-1, c)//上
    dfs(gird: &gird, r+1, c)//下
    dfs(gird: &gird, r, c-1)//左
    dfs(gird: &gird, r, c+1)//右
}
```
1. 图的DFS遍历其实就是多源DFS，单源就是从符合条件的唯一一个节点上下左右出发再次DFS遍历，直到节点不符合条件为止。多源就是对每个入口点做DFS。
2. 图的DFS遍历里可以使用特殊标记（修改图），标记已经遍历过的节点，其实在回溯里也可以理解为剪枝优化。当然前提是对原图的修改不会影响结果。
3. 上面0 表示海洋格子，1 表示陆地格子（未遍历过），2 表示陆地格子（已遍历过）。
4. DFS一般借助递归实现。

### 图BFS遍历访问
BFS访问问题的本质就是让你在一幅「图」中找到从起点start到终点arget的最近距离，模版如下：
``` swift
level = 0
while queue 不空：
    size = queue.size()
    while (size --) {
        cur = queue.pop()
        for 节点 in cur的所有相邻节点：
            if 该节点有效且未被访问过：
                queue.push(该节点)
    }
    level ++;
```
``` swift
func bfsSearch(start: Node, target: Node) -> Int {
    //1.准备队列（避免回头路还需要准备集合）
    var queue = [Node]() 
    var visited = Set<Node>()
    //2.入队出发点（可能有多个出发点）
    queue.append(start) 
    visited.insert(start)
    
    var step = 0 //统计扩散次数
    
    while !queue.isEmpty {
        //3.将队列中的所有节点向四周扩散
        for let _ in queue {
            let cur = queue.removeFirst()
            //4.拿到节点进行处理
            if cur == target { return step }
             
            //5.更新队列（更新时可能需要过滤已被访问的节点）
            for other in cur.others {
               if !visited.contains(other) {
                    queue.append(other)
                    visited.insert(other)
                }
            }
        }
        //更新扩散的次数
        step += 1
    }
    return step
}
```
* 对于图 的 BFS，其实就是「多源 BFS」，树只有一个入口点，图可以有多个入口点。
* 树是有向的因此不需要标识是否访问过，而对于无向图来说，必须得标志是否访问过，并且为了防止某个节点多次入队，需要在其入队之前就将其设置成已访问。
* BFS一般都借助队列实现。

### KMP字符串匹配算法
[图解KMP算法](https://mp.weixin.qq.com/s?__biz=Mzg2NzA4MTkxNQ==&mid=2247485226&idx=1&sn=11318aed06e7b24120256cb3d6c4456d&scene=21#wechat_redirect)
KMP对比蛮力算法的优化在于先进入匹配后，再次发现不匹配时能快速准确的移动并进行下一次必要匹配，忽略了无需匹配的一些情况。

快速准确的前提是pattern字符串内必须具备重复前缀子串（图上A=B）。

先计算出前后缀中的最长共有元素长度表，也叫做部分匹配值。key为字符，value为步进的索引值。以ABCDABD为例，表为0000120，其中第二个字符B对应子串ABCDAB的前缀为[A, AB, ABC, ABCD, ABCDA]，后缀为[BCDAB, CDAB, DAB, AB, B]，共有元素为”AB”，长度为2，这个子串的所有前后缀里共有元素最大长度是2，也就是前后缀AB。

当发现不匹配时，通过已经匹配的字符数量 - 前一个已经匹配字符查表得到的部分匹配值，得到移位的长度。

已经匹配完时，如果还要继续搜索（即找出全部匹配），移动位数 = 待匹配的单词数量 - 0，再将搜索词向后移动7位。
