# 数据结构基础总结

# 基础理解
[数据结构基础理解](bear://x-callback-url/open-note?id=72FBA0D3-38EE-4369-A7CE-D810F2534D3A-3605-000092F2F66BB362)
1. 任何数据结构，其基本操作无非遍历 + 访问，具体一点就是：增删查改。
2. 数据结构种类很多，存在的目的都是在不同的应用场景，尽可能高效地增删查改，高级数据结构的本质就是通过维护一些性质，保证增删查改的效率。
3. 逻辑结构描述的是数据元素被组织起来的逻辑关系，对应各种数据结构。
4. 物理结构描述的是数据元素最终在计算机上的存储关系，对应顺序、链式存储2种，即存储容器为数组或者链表（统称线性表）。
	1. 线性表——>树---->图，这是一种演进路径。
	2. 线性表--->堆栈、队列、串--->数组--->各种线性表。
	3. 二叉树--->各种二叉树---->B树、B+树---->红黑树。
5. 各种数据结构的关系如下：
	* 队列一般用双向链表实现。
	* 栈一般用数组实现就好。
	* 红黑树、AVL树基于二叉搜索树实现。
	* 集合如果用动态数组、单链表则为O(n)，二叉搜索树、红黑树等实现则可以降到log(n)。
	* Map通过二叉搜索树或者红黑树实现TreeMap能达到log(n)的增删查复杂度，大部分情况不考虑key需要具备可比较性的话通过哈希函数配合数组来实现HashMap，能达到O(1)的复杂度。
	* 二叉堆一般用数组实现，依次层序存储。
	* 优先级队列可以用堆实现。
6. 把握一种数据结构，总的来说，体现在它的结构、内在性质、外在特征、操作方法等4个方面，这4个方面是相关的。

# 二叉树基础
[小码哥《恋上数据结构与算法》笔记（七）：二叉树 - 掘金](https://juejin.im/post/5dfb4f07f265da33985632f9)

## 基本概念和性质
1. 节点的度：子节点的个数。
2. 树的度：所有节点度的最大值。
3. 叶子节点：度为0的节点，。
4. 非叶子节点：度不为0的节点。
5. 节点的深度：从根节点到当前节点的唯一路径上的节点总数。
6. 节点的高度：从当前节点到最远叶子节点的路径上的节点总数。
7. 树的深度：所有节点深度的最大值。
8. 树的高度：所有节点高度的最大值。

1. 二叉树：所有节点的度最大为2，且左右子树是有逻辑顺序的，具备如下性质：
	1. 非空二叉树的第i层，最多有2^(i-1)个节点(i >= 1)。
	2. 高度为h的二叉树最多有2^h - 1个节点(h >= 1)。
	3. ::非空二叉树，度为0的节点数n0（叶子结点）和度为2的节点个数为n2，存在n0 = n2 + 1（理解通过总边数相等的推导过程）。::
2. 真二叉树：所有节点的度要么为0，要么为2，没有只有一个子节点的节点。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/2B9E9621-B9AF-42E4-AEDE-F3B77084D4B5.png)
3. 满二叉树：叶子节点全部在最后一层的真二叉树。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/23486FA5-2036-42E3-BB3D-73E6248DEA8F.png)
4. 真二叉树和满二叉树的一些性质：
	1. 满二叉树一定是真二叉树，真二叉树不一定是满二叉树。
	2. 在同样高度的二叉树中，满二叉树的叶子节点数最多，总结点数最多。
	3. 如果满二叉树的高度为h(h >= 1)，那么：
		* 第i层的节点数量：2^(i - 1)
		* 叶子节点数量：2^h - 1
		* 总结点数量 n = 2^h - 1 = 2^0 + 2^1 + 2^2 + 2^3 +…+ h^(h - 1)
		* 高度h = log2(n + 1)
5. 完全二叉树：叶子节点只会出现最后2层，最后1层的叶子节点都靠左对齐。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/9759A4B5-BD53-4659-BC76-DC5AB43A5602.png)
5. 完全二叉树的一些性质：
	1. 完全二叉树从根节点至倒数第2层是一颗满二叉树。
	2. 满二叉树一定是完全二叉树，完全二叉树不一定是满二叉树。
	3. 度为1的节点只有左子树，度为1的节点要么是1个，要么是0个。
	4. 完全二叉树的高度为h(h >= 1)，那么：
		* 至少有2^(h - 1)个节点(2^0 + 2^1 + 2^2 + … + 2^(h - 2) + 1)。
		* 最多有2^h - 1个节点(2^0 + 2^1 + 2^2 + … + 2^(h - 1), 满二叉树)。
		* 总节点数量为 n：
			* 2^(h - 1) <= n < 2^h
			* h - 1 <= log2(n) < h
			* h = floor(log2n) + 1
	5. 一个有n个节点的完全二叉树(n > 0)，从上到下，从左到右对节点从1开始编号，对任意第i个节点：
		* 如果i = 1，它是根节点。
		* 如果i > 1，它的父节点编号为floor(i/2)向下取整树。
		* 如果2i <= n，它的左子节点编号为2i。
		* 如果2i > n，它无左子点。
		* 如果2i + 1 <= n，他的右子节点编号为2i + 1。
		* 如果2i + 1 > n，它无右子节点。
	6. 一个有n个节点的完全二叉树(n > 0)，从上到下，从左到右对节点从0开始编号，对任意第i个节点：
		* 如果i = 0，它是根节点。
		* 如果i > 0，它的父节点编号为floor((i- 1)/2)。
		* 如果2i + 1 <= n - 1，它的左子节点编号为2i + 1。
		* 如果2i + 1 > n - 1，它无左子点。
		* 如果2i + 2 <= n - 1，他的右子节点编号为2i + 2。
		* 如果2i + 2 > n - 1，它无右子节点。
	7. 完全二叉树总节点数量为n ，结合二叉树基本性质n=n0+n1+n2，n0=n2+1，所以n=2n0+n1-1，因为完全二叉树n1要么是1要么是0，可推出::完全二叉树叶子节点数量n0 = floor((n + 1) / 2)=ceiling(n/2)，非叶子节点n1+n2=floor(n/2)=ceiling((n-1)/2)::。（floor和ceiling分别为向下和向上取整）[寻找完全二叉树的叶子节点](https://leetcode-cn.com/problems/find-leaves-of-binary-tree/) 

# 二叉搜索树（BST）
[小码哥《恋上数据结构与算法》笔记（八）：二叉搜索树 - 掘金](https://juejin.im/post/5dfc735ee51d45582d3405de)
1. 二叉搜索树：节点比左子树节点大，比右子树节点小。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/0CC69A79-892C-44E1-8A48-4A97845B05EF.png)
2. 二叉搜索树本质是结合了二分查找的思想把数据组织和维护起来，所以添加、删除、搜索的平均复杂度都是O(logn)，当按照从小到大顺序添加节点时退化成链表。
3. 二叉树的遍历：
	1. 先序遍历：DLR（中、左、右）
	2. 中序遍历：LDR（左、中、右）
	3. 后序遍历：LRD（左、右、中）
	4. 层序遍历：层层遍历。
4. ::前驱节点（predecessor）：中序遍历时的前一个节点，查找前驱节点方法如下：::
	1. 节点信息里没有父节点但是知道根节点：在中序遍历过程中记录更新每次遍历到的节点的前节点pre就能找到。
	2. 节点信息里有父节点，但是不知道根节点：分如下情况
		* 左子树不为空（比如4）：左子树最右边的节点。
		* 左子树为空（比如1、7、9、11）：沿着目标结点的父节点向上找，直到找到一个结点，这个结点的右子树包含目标结点。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/19965192-B0B8-4267-8840-A480E5438109.png)
5. ::后继节点：中序遍历时的后一个节点，查找后继节点方法如下：::
	1. 节点信息里没有父节点但是知道根节点：在中序遍历过程中记录更新每次遍历到的节点的下节点next就能找到。 
	2. 节点信息里有父节点，但是不知道根节点：分如下情况
		* 右子树不为空（比如8）：右子树最左边的节点。
		* 右子树为空（比如3、7、11）：沿着目标结点的父节点向上找，直到找到一个结点，这个结点的左子树包含目标结点。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/26B187C3-57C9-4E54-B3F1-1EAEDC7F3001.png)

# 平衡二叉搜索树（AVL）
[小码哥《恋上数据结构与算法》笔记（九）：平衡二叉搜索树（AVL） - 掘金](https://juejin.im/post/5e057217f265da33d912ecfe#heading-16)
[以后在有面试官问你AVL树，你就把这篇文章扔给他](https://mp.weixin.qq.com/s/dYP5-fM22BgM3viWg4V44A)
1. 平衡二叉搜索树目的是解决二叉搜索树删除节点时可能会退化成链表的问题，维护添加，删除，搜索的复杂度始终维持在O(logn)。
2. 二叉树高度越低平衡性越好，改进二叉搜索树防止退化成链表，维持平衡性是用尽量少的调整次数达到适度平衡（如果追求完美平衡，使得调整次数太多反而增加了时间复杂度）。
3. AVL树和红黑树本质都是在BST基础上对增删查增加了自平衡功能。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/5F313D52-3203-4BC4-B941-78B21BEC6980.png)

[AVL树自平衡总结](bear://x-callback-url/open-note?id=58BD4431-15D0-457D-9FBE-877E2C53A798-407-000001B1EC2D1395)
1. AVL树：维护每个节点的左右子树的高度差不超过1，超过则失衡。
2. AVL失衡的情况：
	1. AVL树添加导致的失衡最坏的情况是所有祖先节点都失衡，但是父节点、非祖先节点都不可能失衡。
	2. AVL树添加后对失衡节点（高度最低的失衡祖先节点）进行旋转处理恢复平衡后，那么往上所有祖先节点都会恢复平衡。
	3. AVL树删除节点可能会导致父节点或祖先节点失衡（只有一个节点会失衡），其他节点都不可能失衡。
	4. AVL树删除后对失衡节点进行左右旋转处理后可能会导致更高处的祖先节点再次失衡，极端情况下，所有祖先节点都需要进行恢复平衡的操作，共O(logn)次调整。
3. 基于BST实现AVL树的原理和实现基本思路：
	1. 首先自平衡的恢复应该是BST添加、删除节点之后。
	2. 基本思想是要通过newNode的parent属性，一路往上遍历访问parent节点，如果访问到的节点失衡（左右子树高度差大于1）就对它进行rebalance操作。
	3. 因为删除后对失衡节点进行rebalance处理后可能会导致更高处的祖先节点再次失衡，所以afterRemove(node) 的实现和afterAdd(node)的区别是前者rebalance后不能return退出当前的parent遍历访问，后者可以直接退出（结合性质1后 2）。
	4. isBalanced的实现可以通过递归思想比较左右子树高度差。
	5. rebalance的实现首先依据是设定g是失衡节点，p是g左右子树高度最高的子节点，n是p左右子树高度最高的子节点，然后分为下面的情况：
		1. LL表示n在失衡节点g的左边子节点p的左边：右旋传（单旋）rotateRight(g)
		2. RR表示n在失衡节点g的右边的右节点p的右边：左旋转（单旋）rotateLeft(g)
		3. LR表示n在失衡节点g的左边子节点p的右边：先rotateLeft(p)变成LL，再rotateRight(g)
		4. RL表示n在失衡节点g的右边子节点p的左边： 先rotateRight(p)变成RR，再rotateLeft(g)
4. ::如何对某个节点（这里是g）进行右旋？::
对某个节点右旋相当于把自己变成原来左节点的右节点。再把原来左节点的右节点挂载它自己的左节点下（如果有的话）（要注意理解上可以这样记，但是实现上要先挂再变，否则节点丢失）。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/917220D0-38E9-46A0-B881-1A143CA45770.png)
	* g.left = p.right
	* p.right = g
	* 让p成为这颗子树的根节点，改变之后整棵树仍然是一颗二叉搜索树：T0 < n < T1 < p < T2 < g < T3，整棵树都达到平衡。
右旋还需要注意维护：
	* T2，p，g的parent属性。
	* 先后更新g，p的高度属性。
5. ::如何对某个节点（这里是g）进行左旋？::
对某个节点左旋相当于把自己变成原来右节点的左节点，再把原来右节点的左节点挂载它自己的右节点下（如果有的话）（要注意理解上可以这样记，但是实现上要先挂再变，否则节点丢失）。![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/A7C5C076-349C-42AC-AACF-FB92B20969D0.png)
	* g.right = p.left
	* p.left = g
	* 让p成为这颗子树的根节点。
左旋还需要注意维护：
	* T1，p，g的parent属性。

# B树、B+树
[小码哥《恋上数据结构与算法》笔记（十）：B树 - 掘金](https://juejin.im/post/5e0aedb8f265da5d5e2419a1)
[为什么MySQL用B树来存储](https://mp.weixin.qq.com/s?__biz=Mzg2NzA4MTkxNQ==&mid=2247486101&idx=1&sn=980f6dfb7643a9ff4f5a661d4a496046&chksm=ce404141f937c85750232523583435e97f3965a3761fa327e5d79e2b720dfced1a1dfc731d3b&token=1321503479&lang=zh_CN#rd)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/7B432E84-B381-4E2E-A71D-19996E772B52.png)
1. B树：一种平衡的多路搜索树，多用于文件系统，数据库的实现，理解上可以看成把BST节点合并起来形成一个超级节点，局部性原理提高搜索命中率。
2. B树特点：
	* 一个节点可以存储超过2个元素，可以拥有超过2个子节点。
	* 拥有二叉树的一些性质。
	* 平衡，每个节点的所有子树高度一致。
	* 比较矮。
3. m阶（m>=2）B树根节点存储元素个数x有1 <= x <= m-1 ，非根节点存储元素个数x有 ceiling(m/2)-1 <= x <= m-1，每个节点的子节点（分叉）个数y有y=x+1，即 ceiling(m/2) <= y <= m，所以4阶B树又称为（2，4）树，表示某个节点最多分叉2-4个子树。
4. B树的搜索：和BST一致，先在节点内部从小到大搜索元素，如果命中，搜索结束，如果未命中，再去对应的子节点中搜索元素，如此重复。
5. B树的定义里因为是满的树，所以添加节点必然是添加到叶子节点的，添加过程同样类似BST。
6. B树添加：
	1. 添加必是添加到叶子结点内。
	2. 添加可能会导致上溢（节点能包含的元素超过最大个数）的情况，解决办法是通过分裂，分裂后有可能再次导致父节点上溢，最极端的情况有可能需要一直分裂到根节点，添加元素导致的上溢，是唯一一种可能导致B树长高的操作。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/A77AF8EC-BF6C-439F-8560-53B45190EAB2.png)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/52C31D1C-3711-44D9-B7E8-7084531C76BD.png)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/3DCDDD21-3399-4934-8B46-A008D29DBCC0.png)
中间元素往上插,把溢出节点分为分裂为左右2个节点，中间元素往上加入到父节点里，保证溢出节点包含元素低于至多限制
7. B树的删除：
	1. 真正删除元素是发生在叶子节点的，如果需要删除叶子直接删除即可。
	2. 删除非叶子节点需要找到前驱或者后继节点（必定在叶子结点内），交换位置后再从叶子节点删除。
	3. 删除元素可能导致下溢的情况（溢节点的元素数量必然等于(m/2(向下取整) - 2)），解决办法是旋转，但是旋转操作可能会导致父节点继续下溢。下溢现象可能会一直往上传播，删除元素导致的下溢是唯一一种可能导致B树变矮的操作。
		1. 如果下溢节点临近的兄弟节点，有至少m/2(向上取整)个元素，可以向其借一个元素。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/F457C82B-8A91-46B0-AE65-1983DC2BFB97.png)
从兄弟节点中借一个元素（最大）放入父节点中，父节点元素往下加入到当前溢出节点里，保证溢出节点包含元素不低于最少限制。这种操作其实就是：旋转。注意子节点d也需要调整。
		2. 如果下溢节点临近的兄弟节点，只有（>= m/2(向上取整) - 1）个元素。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/7BF2D382-A171-4C55-AB19-D729A6118F6B.png)
将父节点的元素b挪下来跟左右子节点进行合并。合并后的节点元素个数等于m/2(向下取整) + m/2(向下取整) - 2，不超过m-1。这个操作可能会导致父节点下溢，依然按照上述方法解决，下溢现象可能会一直往上传播。

8. 知道B+树的场景应用场景？（操作系统、数据库）
知道B+树分为叶子节点和非叶子节点，叶子节点存放具体的值，内部非叶子节点之只存放key，和B树不同的是他的节点内存储的数量为x时，子节点也是x而不是最多x+1。所有叶子节点存储的值通过有序链表连接起来。
9. 知道为什么MySql的索引用B+树实现？为什么不用B树实现？
	1. 因为数据库都是存放在磁盘上的，数据库的IO时间取决于操作系统对磁盘的读取时间并且操作系统读取一次磁盘内容有最小读取单位，所以为了更快的读取磁盘上的数据，一般把B+树内部节点的大小设计成操作系统读取依次磁盘数据的单位大小。
	2. 是因为B+树节点只存储key，能存储更多的索引，树更矮，查找更快，并且因为每次查询都要查到叶子节点，所以更稳定。同时因为叶子节点底部用有序链表相连，做区间查询的时候会更快，只需要从根节点找到一个叶子节点，就能根据链表往后查。

# 红黑树
[小码哥《恋上数据结构与算法》笔记（十一）：红黑树 - 掘金](https://juejin.im/post/5e0da754f265da5d2202025a#heading-2)
[红黑树](bear://x-callback-url/open-note?id=71A1D049-1ED1-42B4-BBE0-E13D52CCF28F-3605-000092F31BB1A7A8)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/7FFC90C2-FE38-4ADA-B0AB-3705074F3635.png)
1. 红黑树：增删后一直维护下面5条性质的二叉搜索树称为红黑树，且一定能实现自平衡。
	1. 节点是RED或者BLACK
	2. 根节点是BLACK
	3. 叶子节点（外部节点，空节点）都是BLACK
	4. RED节点的子节点都是BLACK，RED节点的parent都是BLACK（从根节点到叶子节点的所有路径上不能有2个连续的RED节点）。
	5. 从任意节点到叶子节点的所有路径都包含相同数目的BLACK节点。
2. 红黑树和4阶B树具有等价性，过程是将BLACK节点与它的RED子节点融合在一起后，形成1个B树节点，红黑树的BLACK节点数与4阶B树的节点总个数相等。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/179FE723-00B0-42A0-A61B-7000916F4437.png)
3. 为什么有了AVL树还需要红黑树，二者对比有什么特点？
虽然平衡树解决了二叉查找树退化为近似链表的缺点，能够把查找时间控制在 O(logn)，不过却不是最佳的，因为平衡树要求**每个节点的左子树和右子树的高度差至多等于1**，这个要求实在是太严了，导致每次进行插入/删除节点的时候，几乎都会破坏平衡树的第二个规则，进而我们都需要通过**左旋**和**右旋**来进行调整，使之再次成为一颗符合要求的平衡树，旋转也可能会导致祖先节点失衡，需要不断的向上调整。显然，如果在那种插入、删除很频繁的场景中，平衡树需要频繁着进行调整，这会使平衡树的性能大打折扣，为了解决这个问题，于是有了**红黑树**。

所以，自平衡树是为了解决二叉查找树退化为链表的情况，而红黑树是为了解决平衡树在插入、删除等操作需要频繁调整的情况。

4. 红黑树与哈希表在不同应该场景的选择？
查找速度：哈希更快。
数据量：哈希与数据量无关。
内存使用：红黑树占用内存更少。
5. 红黑树哈希表各种操作的时间复杂度是多少？
红黑树查找和删除的时间复杂度都是O(logn)，Hash查找和删除的时间复杂度都是O(1)。

![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/45FC27E5-2C15-433C-B202-3992FBA177E0.png)
1. 集合特点是不存放重复的元素，所以常用于去重。
2. 集合的增删效率受低层实现的影响，::如果用动态数组、单链表则为O(n)、二叉搜索树、红黑树等实现则可以降到log(n)::。
3. 映射（Map）和字典Dictionary是同一个数据结构接口概念，只是叫法不一样，都是通过某个信息，去找到另一个信息。
4. ::TreeMap 或者HashMap是Map的具体实现。通过二叉搜索树或者红黑树实现TreeMap能达到log(n)的增删查复杂度，大部分情况不考虑key需要具备可比较性的话通过哈希函数配合数组来实现HashMap，能达到O(1)的复杂度。::
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/CC417A5E-A3EB-46B6-A835-7F27CBC32FD7.png)
6. 哈希表是一个典型的空间换时间的应用，哈希值相同的两个对象，不一定相等，只能说两个对象通过hashCode算出的索引值相同。
7. 哈希表的一般实现通过哈希函数算index快速定位到数组的地址位置，从而达到O(1)的访问速度。
8. 解决哈希冲突的方法，一般有如下几种：
	1. 链地址法：冲突的位置存储一个链表的头节点，冲突元素往后头插挂链，之所以头插是因为一般后插入的会频繁访问，可以提高查找效率。[链地址法](https://mp.weixin.qq.com/s?__biz=MzU1MDE4MzUxNA==&mid=2247483679&idx=1&sn=4a51847fb40fafe418bca0b906a03e0a&chksm=fba5362accd2bf3cba68324072863e93a354e65ecb1bdfb9f7dbd857af41f553b72d46b2cb36&scene=21#wechat_redirect)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/AD1B31F3-62A7-4F76-9EED-493AE6D15892.png)
	2. 开放地址：首先看(hash1(key)+0)%7 位置，如果有冲突，就探测（查看）下一个位置：(hash1(key)+1)%7，依次进行。这种探测是线性的，也可以进行平方的探测，但无论如何这种方式是规律的映射，所以容易出现聚集现象，使得探测时间变长。[哈希冲突-开放地址法](https://mp.weixin.qq.com/s/SddKKeTK6Hpk9Q5R8NmZKA)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/F32183BD-40DF-4B22-98EE-2656A6CB525D.png)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/B54CA179-C8F2-4734-985B-3F5B6C4A2484.png)
	3. 再哈希：对冲突的key，再次使用哈希函数。
		* 经过hash1的散列后，会定位到某一个地址，如果这个地址冲突，那么就按照1*hash2(key)、2*hash2(key)… 的偏移去探测合适的位置。
		* 由于Hash2函数不同于Hash1，所以两个不同的关键字Hash1值和Hash2值同时相同的概率就会变得非常低，避免了二次聚集。
		* Hash2函数应该避免hash2(key)=0的情况，因为这样的话探测就失效而原地不动了。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/AAA35918-92AF-4244-A351-C4AFC0000AC1.png)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/A75BEDFE-EB9E-4325-9AA1-70AEAA51E298.png)
9. 哈希函数的设计目标：
	* 尽量让每个key的哈希值是唯一的，更加均匀的分布，减少哈希冲突次数，提升哈希表的性能。
	* 尽量让key的所有信息参与运算。
10. 常见hash_code的生成：
	1. 整数：哈希值则直接为它的值。
	2. 浮点数：将存储的二进制格式转为整数值。
	3. 字符串：把字符转换成ascII码对应的整数值再进行拼凑。
	4. 对象：一般使用地址，特殊的因为相同属性的不同对象地址不同，所以如果要使得相同属性的对象存储时按照同一个对象处理，则需要重写哈希函数，将对象所有属性信息都进行计算得到hash_code而不是利用地址（Swift hasable的处理类似）。
11. 哈希表的装载因子：数组使用量/总长度，一般为0.75，超过后需要动态扩容避免溢出和减少哈希冲突。

1. 堆：维护任意节点的值总是大于等于或小于等于子节点的值，且保证最大最小值永远在堆顶，从而实现获取最大、小值复杂度O(1)，删除最大、小值O(logn)，添加元素O(logn)，
2. 堆的使用场景：
	1. 快速找最值的场景：比如堆排序就是选择排序的一种优化，能快速的选取一个最小/大值。
	2. 优先级问题：::优先级队列的实现底层可以使用堆::，从而使出队的顺序不再是FIFO，而是将优先级最高的元素作为队头优先出队。
3. ::二叉堆：逻辑结构就是一颗完全二叉树，一般用数组实现，依次层序存储。::
4. 添加：将新原素添加到数组末尾，也就是逻辑结构的叶子节点，然后进行上滤操作，大根堆一次上滤一般过程如下：（时间复杂度：O(logn)）
	1. 如果node > 父节点，则与父节点交换位置。
	2. 如果node <= 父节点，或者node没有父节点，则退出循环。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/1C79846C-BB9D-42BC-AFDC-3B17DEED7020.png)
4. 删除：用最后一个节点覆盖根节点后，删除最后节点，再下滤新的根节点，一般过程如下：（时间复杂度：O(logn)）
	1. 如果node < 最大的子节点，与最大的子节点交换位置。
	2. 如果node >= 最大的子节点，或者node没有子节点，则退出循环。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/5EC04753-A4D5-4091-8CB3-1A94153A5694.png)
5. 批量建堆的方式：因为下滤执行最长操作（根到叶子节点）的元素（靠近根节点的元素）最少，而上滤所有叶子节点都要执行最长操作，所以自下而上的下滤效率比自上而下的上滤高。
	1. 自上而下的上滤：自上而下拿到每个元素，然后上滤。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/409ADCC7-B056-4078-87CA-8D7917F096B7.png)
	2. 自下而上的下滤：自下而上拿到每个元素，然后下滤（叶子节点无需下滤）。

# 哈夫曼编码和哈夫曼树

1. 压缩编码原理：压缩编码的本质都是如何用较少的存储空间，表示更大的信息，解码就是拿着这层转换关系去反推原码。
2. 哈夫曼编码：用短码存储较大的信息，用长码表示短的信息，从而达到整体表示信息时所使用的存储空间变得更少。
3. 哈夫曼树原理和构建过程理解：
	1. 如果把字符串“ABBBCCCCCCDDDDDDEE” 转成二进制编码进行传输，则可以得到如下二进制编码。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/0E303DF7-DFD4-45F8-B316-776ACEAF5147.png)
	2. 还可以通过建立哈夫曼树达到更高的压缩率。
		1. 以权值（出现频率）作为根节点构建n棵二叉树，组成森林。
		2. 在森林中选出2个根节点最小的树合并，作为一颗新树的左右子树，且新树的根节点为其左右子树根节点之和，再从森林中删除刚才选取的2棵树，并将新树加入森林。
		3. 依次合并森林。 ![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/9825A03E-FE8D-4AF2-8D52-31FFBAAC03B9.png)![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/D25062EC-6306-490A-9A5B-DE3EA05B23AD.png)
1. 哈夫曼树的特点：
	1. 权值节点全部在叶子节点，保证访问路径唯一，路径唯一就可以通过路径来绝对的表示信息（编码场景下每个哈夫曼编码都不是另一个哈夫曼编码的前缀）。
	2. 权值大的（出现频率高的）离根节点越近，从根到它的路径长度也就越短，所以哈夫曼树是带权路径长度最短的树（编码压缩）

# Trie字典树
[小码哥《恋上数据结构与算法》笔记（十六）：Trie - 掘金](https://juejin.im/post/5e6663576fb9a07c8b5bc354)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/13ECBAEF-E6D5-45AC-8BC1-D1F0096B4559.png)
1. 字典树的主要应用场景：搜索提示和敏感词过滤，每个分支路径上表示一种匹配的可能性。假设使用 Trie 存储 cat、dog、doggy、does、cast、add 六个单词。要查找dog，首先在根节点搜索有没有d子节点，然后再查看d节点下是否有o子节点，最后在o节点下查看是否有g子节点。
2. 特点： 
	1. 典型的空间换时间，利用字符串的公共前缀来降低查询时间的开销已达到提高查询的目的。
	2. 最大限度的减少无谓的比较，查询效率比哈希高，查询效率主要跟字符串的长度有关。
3. 实现注意：
	1. node里需要有容器集合能容纳所有的字符，用来表示分支。
	2. node里还要包含一个标志信息，记录是否到底。
	3. ::可以通过set或字典来实现一个Trie。::
	4. 如果敏感词的长度为 m，则每个敏感词的查找时间复杂度是 O(m)，字符串的长度为 n，我们需要遍历 n 遍，所以敏感词查找这个过程的时间复杂度是 O(n * m)。如果有 t 个敏感词的话，构建 trie 树的时间复杂度是 O(t * m)。
	5. 具体参考这里[字典树和敏感词过滤](https://mp.weixin.qq.com/s/ZYtU4v9y2KMLT0d2X_MIZQ)，主要是利用双指针在给出的字符串上移动，然后再去字典树里匹配所指的区间范围内的子串。

# 并查集
<a href='%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/02-%E5%B9%B6%E6%9F%A5%E9%9B%86.pdf'>02-并查集.pdf</a>
1. 设计思想：通过分门别类的思想从而达到快速查找的目的。
2. 实际场景：单个元素组成小集合，不相交的小集合又组成大集合，要在大集合内判断2个元素是否属于一个小集合时，可以使用并查思想。
	1. 张无忌和杨过打架之前，先判断是否是同一门派，这就涉及到了并查集的查找find操作。
	2. 张无忌和杨过觉得俩人合得来，那就合并门派，这就涉及到了并查集的合并union操作。
	3. 每一个门派都有一个掌门人，这涉及到了并查集的存储方式，掌门人代表了这个门派的根节点。
3. 特点：每个小集合内有一个特殊元素，它代表着这个小集合内元素在物理存储结构上的一种抽象，通过它区分了多个小集合的存储，从而快速的判断2个元素是否处于同一集合。
4. ::实现上存储方式的理解：假如处理的是整数，那么可以用数组来存储成如下样式。::
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/D28A6F28-820D-45EE-B510-48165E3D98B2.png)
	1. 索引为0、1、3的位置，存储的值都是1，说明他们属于同一个小集合，并且小集合通过索引为1的相同元素值1来代表。
	2. 索引为2的单独属于一个小集合，并且小集合通过索引为2的相同元素值2来代表。
	3. 索引4、5、6、7单独属于一个小集合，并且小集合通过索引为6上的相同元素值6来代表（图上有错误，4存储的是6）。
1. Union操作O(logn)：合并2个元素使得它们处于同一集合，相当于建立2个元素之间的关系，比如union(v1, v2)表示让v1的根节点指向v2的根节点（注意是根节点，其他节点存储信息不变）
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/920D2912-BB70-4BBA-9182-4CA47EBA3283.png)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/6D402DC3-6AB4-400F-87E6-F9BCEAEC3A68.png)
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/DE889220-A6B4-4635-A468-60B6C494BB8D.png)
2. find操作O(logn)：查找某个元素所属的小集合，返回小集合的代表元素（派别）。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/5B7EFB5B-89BA-419B-BCF8-015D12E78AF5.png)
3. 问题和优化：union的时候，随意的将A的上级指向B，可能导致逻辑指向关系形成链表，导致find的复杂度升高，常见方案如下：
	1. 基于size：判断一下find到的root1和root2谁的子节点多，谁多谁做上级领导。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/B930A5C4-8CCE-4ADA-A1CC-7598F3567CAE.png)
	2. 路径压缩：find时把所有路径上的节点全部指向根节点，降低树的高度，提升查找效率。
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/69D1753B-D926-4D85-B433-1B8EAEC4E4E2.png)

# BloomFilter
<a href='%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/09-%E5%B8%83%E9%9A%86%E8%BF%87%E6%BB%A4%E5%99%A8.pdf'>09-布隆过滤器.pdf</a>
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/7A1F5686-8DEB-4F77-80E3-421979BB2B9A.png)
1. BloomFilter的适用场景是经常需要判断1个元素是否存在并能保证空间效率，这也是为什么不用hashSet、hashMap的原因。
2. 本质是哈希表的一种更高级结构，添加的时候通过多个哈希函数映射几个不同的index值，然后把二进制位上第index位的值都存为1。查找的时候如果有一个哈希函数得到的结果index位置上存储的不是1，这个元素肯定不存在，都为1则认为存在（实际不一定）。
3. 优点是空间和查询效率比一般数据结构高，缺点是存在误判，只能保证一定不存在，不能保证一定存在。
4. 添加查询的效率为O(k)，k为哈希函数个数，空间效率为O(m)，m为用来存储的二进制位数。
5. BloomFilter的误判率和二进制位数，hash函数个数、数据规模有关，所以一般设计BloomFilter时是根据已知的误判率去设计hash函数的个数和二进制位数。

# 跳表（SkipList）
<a href='%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/10-%E8%B7%B3%E8%A1%A8.pdf'>10-跳表.pdf</a>
![](%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84%E5%9F%BA%E7%A1%80%E6%80%BB%E7%BB%93/C5C24A38-88A1-44ED-8E6B-9E779F110A6D.png)
跳表主要是为了优化链表的增加、删除、查找速度为O(logn)，最初的目的也是为了取代平衡树。
跳表是按层构建的，底层是一个有序链表，上层是下层的快速通道。
