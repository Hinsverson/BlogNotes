# H264编解码
以时间换空间的形式，来降低视频存储容量。

*I帧：关键帧，采用帧内压缩技术*.
*P帧：向前参考帧，压缩时需参考前一个I帧或P针，帧间压缩技术*.
*B帧：双向参考帧，压缩时即参考前一帧也参考后一帧，帧间压缩技术.*
*IDR帧：是第一个I帧，为的是和其他I帧区别开，方便控制编码和解码*

> 一个序列的第一个图像叫做 IDR 图像（立即刷新图像），IDR 图像都是 I 帧图像。引入 IDR 图像是为了解码的重同步，当解码器解码到 IDR 图像时，立即将参考帧队列清空，将已解码的数据全部输出或抛弃，重新查找参数集，开始一个新的序列。这样，如果前一个序列出现重大错误，在这里可以获得重新同步的机会。IDR图像之后的图像永远不会使用IDR之前的图像的数据来解码。  

> I帧的压缩率是7（跟JPG差不多），P帧是20，B帧可以达到50. 但是iOS中一般不开启B帧，因为B帧的存在会导致时间戳同步较为复杂.  
> 在可以接受一定度的延时，需要比较高的压缩比就可以大量使用B帧。  
> 需要提高时效性（直播）的情况，就不能大量使用B帧，因为它在解码时需要向前向后参考，需要等后一针来了才能正确解码。  

# DTS和PTS
* DTS：解码顺序，主要用于视频的解码，在解码阶段使用。
* PTS：显示顺序，主要用于视频的同步和输出.在渲染的时候使用。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/2C6BC040-E858-41DE-BAB8-641E06249B94.png)
I帧的解码不依赖于任何的其它的帧，而P帧的解码则依赖于其前面的I帧或者P帧，B帧的解码则依赖于其前的最近的一个I帧或者P帧 及其后的最近的一个P帧。

**在没有B frame的情况下.DTS和PTS的输出顺序是一样的。**

## 编解码压缩本质是去除冗余信息。
1. 空间冗余：视频的背景和整体颜色相近并且平稳变化，可以利用帧内编码进行压缩（无损）
2. 时间冗余：两个视频帧之间具有强相关性，利用/运动估计/和/运动补偿/进行帧间压缩（无损）
3. 结构冗余：图像内部存在相似性，通过这种关系可以进行 [分形编码](http://baike.baidu.com/link?url=OfBs_OYCdMlOPgKmPA86-tRq3rb2lMmLySxFgRBAaBi2L-JRpwzEecjB-apT2VwkByKoAumv6ukD-xgVRssS8p61eE1quvMjaWxTcpghvJH6vqPNF50TBofDdoKctrin) ;
4. 编码冗余：出现概率大的颜色编码长度短，概率小的颜色编码长度长；（可变长度编码）
5. 视觉冗余：利用人眼对亮度和色度的敏感度不同，在编码时进行数据压缩；（有损压缩）

## 针间压缩常用技术手段原理：
1. *运动补偿*：运动补偿是通过先前的局部图形来预测，补偿当前的局部图像.它是减少帧序列冗余信息很有效的方法。
2. *运动表示*：不同区域的图像需要使用不同的运动矢量来描述运动信息。
3. *运动估计*：运动估计就是从视频序列中抽取运动信息的一整套技术。

# H264压缩的原理和理解
1. 划分宏块
2. 对每一帧进行针内压缩并存储宏块的预测模式和残差数据。
3. 将帧分组并进行针间压缩，存储关键帧和运动补偿数据，。

## 进行针内压缩并存储预测模式和残差数据
每个宏块划分好后会进行预测模式的选定，预测模式的选择就是说使用哪一种相关性来进行颜色值的计算。

*基本原理理解*
1. 一张原始图通过预测模式计算得到一张预测图。
2. 计算帧内预测残差值（和原图的差异）。
3. 保存残差数据和每个宏块选择的模式信息数据。
4. 解码时首先通过宏块的模式信息计算出预测图，然后将预测图与我们的残差值进行累积，就能还原成原图像。

> ⚠️实际压缩保存的是残差数据和每个宏块选择的模式信息数据。  

### 预测模式原理和理解
对于一幅图像，相邻的两个像素的亮度（Y）和色度值（UV）之间经常是比较接近的，也就是颜色是逐渐变化的，不会一下子突变成完全不一样的颜色。而进行视频编码，目的就是利用这个相关性，来进行压缩。不管是帧内预测、帧间预测、变换、量化、熵编码，一切的一切都是为这个目的服务的，而压缩模式的选择就是选择使用哪一种相关性。

*预测模式*
4x4的亮度块（Y）有9种预测模式。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/B5C78499-58EB-4192-B182-35685EE13A23.png)
预测模式0（vertical），当前块的十六个像素值，完全由其上方块最后一行的那四个像素值决定，第一列所有的Xp值都等于A，第二排都等于B，以此类推。
预测模式1（horizontal）也是一样，完全由图中IJKL四个像素值决定。
预测模式2（DC），则十六个像素值完全相等，等于ABCDIJKL这八个像素的平均值。
预测模式3-8，倾斜方向的，各个像素是由A到L像素通过权重不等的公式加权计算的。

16x16的亮度块有4种预测模式
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/D43531D7-9597-4C7D-BB01-6C0AEE296AF5.png)

### 针内压缩流程理解
1. 选定预测模式后计算的预测图，但和原图是有差别的，原图比较圆润，预测图相对而言比较粗糙。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/A81FABF8-4869-4680-8DFA-92504148422B.png)

2. 计算帧内预测残差值，底下的图就是我们的原图，通过预测与原图的差得出一个结果，这个灰色图就是残差值。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/70FEA81D-E9F1-4585-A978-261DB1955EFE.png)

3. 拿到参差值之后，我们就进行压缩，压缩时保存残差数据和每个宏块选择的模式信息数据。那么有了这2个数据之后，当我们解码时首先通过宏块的模式信息计算出预测图，然后将预测图与我们的残差值进行累积，就能还原成原图像，那这个过程就是”帧内压缩技术”的基本原理过程。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/D9008531-27CE-4D1F-A35E-65E8A90F99B8.png)

## 将帧分组并进行针间压缩
对比针内的冗余，时间上的数据冗余是最大的，假设摄像头每秒抓取30帧，这30帧的数据大部分情况下都是相关联的，其实我们只需要保存一帧的数据，其它帧都可以通过这一帧再按某种规则预测出来，这就是针间压缩的原理。

*基本原理理解*
1. 按顺序比对针间差异，进行针分组。
2. 分组后确定I、B、P针，只完整保留I针数据。
3. 再通过运动矢量计算得到组内针间的运动补偿数据并存储下来，通过运动补偿数据和关键针就可以确定其他针。

### 针间压缩流程理解
1. H264编码器会按顺序，每次取出两幅相邻的帧进行宏块比较，计算两帧的相似度。其算法是：在相邻几幅图像画面中，一般有差别的像素只有10%以内的点,亮度差值变化不超过2%，而色度差值的变化只有1%以内，我们认为这样的图可以分到一组。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/9190E63E-0006-400B-B2A4-A21BA6BB0B5A.png)

2. 在这样一组帧中，经过编码后，我们只保留第一帖的完整数据，其它帧都通过参考上一帧计算出来。我们称第一帧为*IDR／I帧*，其它帧我们称为*P／B帧*，这样编码后的数据帧组称为*GOP*。![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/0F882780-7FA2-4F97-A0CA-E3DA5F23BA4C.png)

3. 在H264编码器中将帧分组后，就要计算帧组内物体的运动矢量了。首先按顺序从缓冲区头部取出两帧视频数据，然后进行宏块扫描。当发现其中一幅图片中有物体时，就在另一幅图的邻近位置（搜索窗口中）进行搜索。如果此时在另一幅图中找到该物体，那么就可以计算出物体的运动矢量了（比如通过下图中小球的位移差，计算出台图运行的方向和距离）。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/B154CCEE-58D5-4713-AC95-D4B63D30E1CC.png)

4. 运动矢量计算出来后，将相同部分（也就是绿色部分）减去，就得到了补偿数据。我们最终只需要将补偿数据进行保存，以后在解码时就可以恢复原图了。压缩补偿后的数据只需要记录很少的一点数据。
![](H264%E5%8E%8B%E7%BC%A9%E8%BF%87%E7%A8%8B%E5%92%8C%E5%8E%9F%E7%90%86%E7%90%86%E8%A7%A3/7ED17537-D74D-46FC-BD22-94F85A83A43D.png)

> tips：一般花屏是因为你丢了P帧或者I帧，导致解码错误.。而卡顿是因为为了怕花屏，将整组错误的GOP数据扔掉了。直达下一组正确的GOP再重新刷屏，而这中间的时间差,就是我们所感受的卡顿。
